Privacy policy

Operator review edition. Public operator identity and contact details require confirmation before verification resubmission.

1. Introduction and application identity

AgentFlow AI Backup is an operator-controlled tool for encrypted backup and recovery of the separate, private AgentFlow AI application. This public website provides information about that integration. It does not offer public backup accounts, Google sign-in, or a general Google Drive file-management service.

2. Who operates the integration

The integration is managed by the AgentFlow AI project operator and authorized recovery personnel. The operator controls the connected Google account and backup environment. The public materials do not yet establish the operator?s legal name or a verified public contact address; see Operator contact before authorizing access.

3. Purpose of Google Drive access

Google Drive is the operator-selected off-site storage location for encrypted database archives. Authorization allows rclone, the transfer client, to upload backup ciphertext and retrieve it for integrity checks and recovery. Google authorization is performed separately in the operator?s environment, not on this website.

4. Google account and Drive data accessed

Google handles account selection and consent. The backup adapter does not implement Google profile, email, contacts, Gmail, or calendar collection. It works with backup file contents in encrypted form and the file/folder metadata needed by rclone, such as names, identifiers, paths, sizes, modification times and available checksums. Google may return account or service metadata to rclone as part of API operation; the adapter does not build a user profile from it.

5. Exact OAuth permission

The intended permission is https://www.googleapis.com/auth/drive.file. It permits access to files created by the app or specifically opened/shared with it through supported authorization mechanisms. For this rclone integration, the documented workflow uses files and folders created through rclone with the configured OAuth client. Selecting a folder path does not itself grant access to an arbitrary pre-existing folder. The tool is not intended to read or manage unrelated Drive files. No broader Drive, profile, email or OpenID scopes are specified by the backup scripts. The adapter uses an already-authenticated remote and cannot enforce its granted scope: the operator must confirm the actual grant before use. The live grant was not inspected for this policy review.

6. Authorization and refresh tokens

rclone uses OAuth access tokens to call Google Drive and refresh tokens to obtain replacement access tokens without repeated consent while authorization remains valid. Tokens and OAuth client configuration are managed in the operator?s local rclone profile, outside this website and source control. They are credentials and must be protected by the operator. Revoked or expired authorization stops transfers; Google Testing-mode authorization is not a durable unattended-operation guarantee.

7. Creating and uploading encrypted backups

The local tool creates a PostgreSQL archive in temporary working storage, verifies it, encrypts it, then decrypts a local verification copy and checks archive integrity before delivery. The Drive adapter accepts one correctly named .age artifact with an age header and a matching local checksum manifest. Only the ciphertext file is passed to rclone for upload. Plaintext dumps, local manifests, private recovery identities and OAuth credentials are not included in that upload. The upload uses an immutable copy operation to refuse conflicting replacement; this is not a Google Drive retention lock.

8. Listing, downloading and verification

rclone resolves the backup destination and metadata within its authorized file access. The adapter performs a full readback check limited to the uploaded filename. An authorized operator can separately download the encrypted file for recovery, compare its SHA-256 with the protected local record, decrypt it with the matching identity, validate the archive, and restore into an isolated database. A successful checksum check alone does not prove successful restoration.

9. Application metadata and operational logs

Local manifests include timestamps, artifact names, encryption format, database identity/version and archive/ciphertext checksums. Local transfer reports include the remote object path and integrity status. Scheduler logs record completion time, outcome, artifact/checksum and whether a failure alert was sent. Raw rclone diagnostics are suppressed by the adapter. If configured, a webhook receives a generic backup failure message, not archive contents or credentials. This site has no forms, analytics scripts or application cookies; Vercel may process ordinary hosting request data, including IP addresses and request information, under its own practices.

10. Storage and protection

Encrypted archives are stored locally and in the operator-selected Drive destination. Manifests, transfer reports and logs remain local in the reviewed workflow. Temporary plaintext exists during backup verification and recovery; temporary-directory cleanup is not guaranteed secure erasure, and interruptions may leave recoverable data. The operator must restrict local storage and account access. This static site does not store backup contents or OAuth tokens. Drive and Vercel operate under their respective privacy policies.

11. age/X25519 encryption

New command-line backups use age authenticated encryption with X25519 recipients through the age executable. Encryption happens locally before the upload. Drive receives ciphertext, but can still observe file metadata such as names, sizes and upload times. Encryption does not protect a compromised host or a disclosed private identity. Losing the required private identity can make recovery impossible.

12. Private recovery key custody: tested and planned

The synthetic recovery drill kept the private age identity in a separate local recovery directory and uploaded only ciphertext. The code rejects keys located inside the spool or backup destination. The current backup verification process needs access to the private identity locally to decrypt a verification copy; a public-recipient-only worker is not established by this implementation. Managed/offline vaults, separate custodians, audited retrieval and independent recovery copies are documented operational requirements, not verified deployed controls. Private identities must never be stored with Drive archives or published on this site.

13. Sharing and third parties

Google Drive receives encrypted backup files and associated metadata as the selected storage provider. Vercel hosts this informational website. rclone and age run locally as tools; they are not additional archive hosting destinations in this workflow. An operator-selected alert provider receives a generic failure message only when configured. Authorized recovery personnel can access archives and recovered data as required for recovery. Google user data is not sold, used for advertising, marketing profiles or AI model training. Any disclosure required by law must be limited to the applicable requirement.

14. Retention, deletion and restoration

Remote deletion is not implemented by the transfer adapter. The operator manages Drive retention and deletion. Thirty daily backups plus twelve monthly backups are a recommendation awaiting approval, not an active retention commitment. Local retention tooling defaults to a dry run; deletion requires explicit confirmation. No fixed retention period for logs, tokens, local artifacts or hosting records has been established in the reviewed evidence. Revocation does not delete stored archives. To remove backup information, the operator must address Drive copies and trash, local archives, restored copies and logs as applicable; provider retention may delay final removal. Recovery may reintroduce previously backed-up data and requires review of deletion requests before returning restored data to use.

15. Revoke Google authorization

Visit Google Account third-party connections, select the application and remove its access. This prevents further authorized API access but does not erase existing backup files. The operator should also remove obsolete local rclone tokens/configuration securely. Reauthorization may be necessary for future backups; existing files may not automatically become accessible under a new grant.

16. Access and deletion requests

The connected account holder can inspect accessible backup objects in Google Drive and use Google?s account controls. Requests concerning local logs, archives or data contained in the private application?s backups must go to the operator, who must verify authority before disclosure or deletion. Do not send passwords, tokens, recovery keys or database exports with a request. A public request channel has not yet been verified; this is an outstanding publication requirement.

17. Security measures and limitations

Implemented checks include encryption before upload, local archive verification, ciphertext checksums, remote readback verification and restricted upload input validation. Synthetic recovery has passed. Daily scheduling is implemented but disabled by default; production unattended backup readiness is not established. Access controls, key custody, alert routing, retention and restoration procedures depend on operator configuration. No certification, guaranteed availability, recovery time or absolute security is claimed.

18. Google API Services User Data Policy

Use of information received from Google APIs will adhere to the Google API Services User Data Policy, including applicable Limited Use requirements. Google data is used only to provide the disclosed backup, integrity verification and recovery functions. It is not used for advertising or generalized AI training. Transfers and human access must be limited to permitted purposes, including authorized recovery, security investigation or legal requirements, with consent where required.

19. Changes to this policy

Updates will be published here with a revised effective date. Material changes to Google data use must be disclosed before the changed use begins, with renewed consent where required. Publishing this policy does not establish Google approval.

Until a public channel is supplied, existing authorized participants should use their established private operator contact.
